# Example output

Standing up six models and 74.5 GB of weights is a lot to ask before you know whether the
output is any good. This is a real report, generated by the pipeline in this repository
against `tests/fixtures/vulnerable_apps/express_idor`, committed so you can read it first.

```sh
uv run sentinel review tests/fixtures/vulnerable_apps/express_idor \
    -o examples/express_idor-report --format both
```

`report.md` is the human artifact. `report.json` is the same content plus the full audit
trail: every candidate that was suppressed, which gate dropped it, and why. `metrics.json`
carries per-node latency, per-model token counts, and the cache hit rate.

Read `report.json` rather than `report.md` if you want to judge the design. The suppressed
candidates are where the grounding guarantee and the applicability gate show their work,
and they are the reason to trust the two findings that survived.

Two things worth checking in any report before you trust its numbers. `summary.complete`
tells you whether the run accounted for the whole target. `metrics.json` `cache_hit_rate`
tells you whether you are looking at fresh inference or a replay of an earlier run.

This fixture is deliberately vulnerable and deliberately small. It is a smoke test of the
pipeline, not a benchmark. Public benchmark results are not published yet, and `evals/`
explains why.
